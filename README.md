# TaskChain — 角色沉浸扮演

让 AI 在说"我去泡杯咖啡"之后，不再是下一秒就把咖啡端来，而是**真的等一会儿再去端**。
每一件小事都被登记、都会被推进——这就是时间的纹理。

## 问题

传统 chatbot 最大的"出戏点"：AI 说"我去泡咖啡"，然后**立刻**说"咖啡好了，趁热喝"。
没有"正在做"的过程，没有中途的碎碎念，也没有完成时的自然回场。
用户在沉默中等待，AI 在虚空中秒回——这不是角色扮演，是台词拼接。

## 解决了什么

| 没有插件时 | 有插件时 |
|-----------|---------|
| "我去泡咖啡" → 秒回"给，咖啡" | "我去泡咖啡" → 等 5 分钟 → "咖啡好啦！" |
| 等待期间完全沉默 | 中途搭话："加糖还是加奶？" |
| AI 说了就等于做了 | AI 说了 → **正在做** → 做完了 |
| 用户回什么 AI 就答什么 | AI 会主动找话题、问偏好、吐槽 |
| 对话是一条直线 | 对话有起伏、有等待、有回报 |
| /reset 后旧任务还在跑 | 旧对话的任务自动清 |

## 插件配置

通过 AstrBot 配置面板修改：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `interact_enabled` | bool | `false` | 启用中途互动（长任务中主动插入检查点找话题聊天）。不开启时插件只负责登记时间→到点回调 |

## 核心机制

```
用户："帮我泡杯咖啡"
  │
  ├─ AI 调用 chain_task create {name:"泡咖啡", duration:5}
  │   工具注入规则：任何需要等待的动作，必须登记
  │   工具返回：[任务已安排] 预计14:32完成 → 告知AI任务刚开始
  │   AI 按人设简短回应，不提前问口味
  │
  ├─ [30~60s 后] 中途互动触发（需开启 interact_enabled）
  │   ├─ 用户回复了 → 自然聊几句
  │   └─ 用户没回 → 45~90s 后 50% 概率由 LLM 决定发句简短的
  │        (如"还在吗？""嗯哼？"——不超过8个字)
  │
  ├─ [主任务最后 10 秒进入完成监听]
  │   如果用户在这期间发消息 → 立即告知AI已完成 → AI直接给结果
  │   避免"AI刚要回调、用户又发消息、时序错乱"
  │
  └─ [N 分钟后] 主任务完成
      ├─ 有对话上下文 → 结合聊天记录自然回应
      ├─ 用户一直没回 → 自行决定结果说出来
      └─ LLM 调用失败 → 使用兜底文案，不会沉默
```

## 架构

```
chain_task 工具 (create/list/cancel/advance)
    │
    ├─→ 任务链存储 (JSON 持久化，重启恢复)
    │
    ├─→ 调度器 (每10s tick，到点触发回调)
    │      │
    │      ├─→ 中途互动點 → LLM 生成找话题
    │      ├─→ 完成监听 → 最后10s窗口，用户优先
    │      └─→ 主任务完成 → LLM 生成完成回复
    │
    ├─→ on_llm_request 钩子 (每次 LLM 请求前注入)
    │      ├─ TOOL_USAGE_SYSTEM_PROMPT → 告诉AI何时必须调用
    │      └─ 当前任务链状态 → 防止AI提前说完成
    │
    ├─→ 回复守卫
    │      ├─ 检测AI是否途中说了"好了" → 替换为进行中安全文案
    │      ├─ 检测完成回复是否过于机械 → 替换为自然兜底文案
    │      └─ send_message 失败 → 回滚任务状态，最多重试3次
    │
    └─→ 会话隔离
           ├─ 任务绑定 conversation_id
           ├─ 新对话/reset → 旧链自动取消
           └─ 同一用户不同对话互不干扰
```

## 典型场景

### 泡咖啡
```
博士: 帮我泡杯咖啡
佩佩: [调用 chain_task create] → "好嘞，交给我吧！"
──── 约 40s 后 ────
佩佩: 博士，加糖还是加奶呀？我这边豆子磨得可香了 ☕
博士: 加糖，两块
佩佩: 两块够甜吗？萨尔贡的粗糖可是很够劲儿的～
博士: 够了够了
──── 约 5min 后 ────
佩佩: 咖啡好啦！给你加了两块糖，趁热喝～（把杯子轻轻放你手边）
```

### 学习
```
博士: 我去看会网课
佩佩: [调用 chain_task create] → "好呀，我不吵你"
──── 约 50s 后 ────
佩佩: （咬着笔杆偷看屏幕）这老师讲话好催眠啊……😴

[博士继续学习，没有理她]
──── 约 70s 后 ────
佩佩: （翻了一页书，小声嘟囔）博士还在学啊……

──── 约 30min 后 ────
佩佩: 博士，这一章讲完了吗？我刚才偷听了一段，那个公式推导好离谱！
```

### 拿东西
```
博士: 帮我从资料室拿一下上次的拓片
佩佩: [调用 chain_task create] → "好嘞，我去翻翻～"
──── 约 40s 后 ────
佩佩: 博士，是卷起来的那张还是裱在板子上的？我记得有三份！
博士: 裱板子的
──── 约 3min 后 ────
佩佩: 找到啦！给——比上次又黄了一点，要不要我拿密封袋装一下？📜
```

## LLM 工具接口

**`chain_task`** — AI 通过此工具管理所有后台任务

| 操作 | 说明 | 必传参数 |
|------|------|---------|
| `create` | 创建新任务（同时取消同会话旧任务） | `tasks_json`: `[{"name":"泡咖啡","duration_minutes":3}]` |
| `list` | 查看当前活跃任务及剩余时间 | — |
| `cancel` | 取消指定任务 | `chain_id` |

**工具规则注入**（自动附加到每次 LLM 请求的 system_prompt）：

> 当你准备承诺一个需要等待的动作时，必须先调用 chain_task。
> 包括：泡茶/咖啡、做饭、拿东西、去厨房/仓库、整理材料、查资料、找物品等。
> 如果是自己临时想做、主动提议的下一步行动，也必须创建任务。
> 不要只在文字里承诺未来动作而不登记。

## 默认行为

插件启动后自动注册 `chain_task` 工具，无需额外配置。
数据持久化到 `data/plugin_data/astrbot_plugin_taskchain_tool/task_chains.json`。

可调常量：
- `MIN_TASK_SECONDS = 10` — 单任务最短 10 秒
- `COMPLETION_LISTEN_SECONDS = 10` — 完成监听窗口
- `FOLLOWUP_PROBABILITY = 0.5` — 用户没回时跟进的概率
- 中途互动：30~60 秒随机，仅当任务 ≥ 2 分钟时插入
